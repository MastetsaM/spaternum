# Spec — Notes (phase 1)

## What and why
Markdown notes, organised in folders and tags, available on PC and Android and **usable offline**. The first module of phase 1 together with voice notes ([[PRD]]). Notes are also the main text the later RAG system searches.

## Data model
Owned by the notes module. Plain SQL ([[2026-10-21-database-access-plain-sql]]).

```sql
CREATE TABLE note_folders (
    id          uuid PRIMARY KEY,                  -- generated by the client
    parent_id   uuid,                              -- NULL = top level; any depth
    name        text NOT NULL,
    created_at  timestamptz NOT NULL,
    updated_at  timestamptz NOT NULL,              -- latest write wins
    archived_at timestamptz,                       -- NULL = active
    seq         bigint NOT NULL                    -- server-assigned on every write; sync pulls by this
);

CREATE TABLE notes (
    id          uuid PRIMARY KEY,                  -- generated by the client
    folder_id   uuid,                              -- NULL = no folder
    title       text NOT NULL DEFAULT '',          -- optional; empty = the body's first line is shown
    body        text NOT NULL DEFAULT '',          -- Markdown
    tags        text[] NOT NULL DEFAULT '{}',
    pinned      boolean NOT NULL DEFAULT false,
    created_at  timestamptz NOT NULL,
    updated_at  timestamptz NOT NULL,              -- latest write wins
    archived_at timestamptz,                       -- NULL = active
    seq         bigint NOT NULL                    -- server-assigned on every write; sync pulls by this
);
```

Choices:
- **Optional title** (added 2026-10-28, Mihail; migration `002_note_title.sql`). When it's empty, the first line of the body is shown as the title, so quick capture on the phone still needs no title. This is the same rule as voice notes. Existing notes get an empty title and keep showing their first line.
- **Markdown** — plain text is valid Markdown, so phase 1 can start with a plain text box and add rendering later without changing data.
- **Tags as `text[]`** with a GIN index — one column, simple queries; renaming a tag means updating every note that has it (acceptable for one user).
- **Folders nest to any depth**, and belong to the notes module only — other modules have their own.
- **Pinned** — unlimited; pinned notes show at the top of their folder.
- **Sort order** inside a folder: pinned first, then **last edited first**.
- **Archive, never delete** — `archived_at` marks an archived row; the server keeps it.
- **Client-generated UUIDs** — notes can be created offline.
- **No foreign keys**, not even inside the module (decided 2026-10-25): after being offline, the app pushes folders and notes separately and in no fixed order, so a note can reach the server before its folder. A foreign key would reject it and block sync. The code handles a missing folder (note shows at the top level).
- **`[[wikilinks]]`** — allowed in the body as plain text from day one. No links table in phase 1; one can be built later by parsing existing notes (backlinks, RAG context).

## Empty notes
A note is empty when **both the title and the body** are empty, where only spaces or new lines also count as empty. An empty note is never saved. A note with only a title is fine.
- **New note** left empty → never created, locally or on the server.
- **Existing note** cleared to empty → the change is discarded and the note goes back to what it was. To get rid of a note, archive it.

## Archiving
Archives live **only on the server**, never on the devices ([[2026-10-21-sync-rxdb]]).
- Archiving a note removes it from the device's local database; the server sets `archived_at` and keeps the row.
- **Archiving a folder** archives everything inside it — notes and sub-folders, any depth — all with the same `archived_at`.
- **Restoring a folder** restores everything that was archived with it (same `archived_at`); items archived separately before stay archived.
- Archived items are viewed and restored on the app's **shared Archive page** (online only), not inside the notes screens. Restored items sync back to every device as a normal change.
- The Archive page shows **one entry per thing archived**: an archived folder is one entry ("Folder X, 50 items"), not one per note inside it. A note archived on its own is its own entry.
- Restoring marks the restored items as just edited (`updated_at` = now), so an older pending change from another device can't undo the restore.
- The notes module provides `list_archived()` and `restore(id)` for the archive module ([[2026-10-20-architecture-modular-monolith]]).

## Search
On the device, over local (non-archived) notes: **"contains this text"** on the title and the body, plus **filter by tag**. Works offline; no server code. Archived notes aren't searched locally. Smarter search comes with RAG later.

## Offline and sync
Notes work offline on both clients; changes sync when the server is reachable, latest `updated_at` wins ([[2026-10-20-offline-latest-write-wins]]). Sync tool: RxDB on the client with pull/push endpoints on the server, proven by the sync spike ([[2026-10-21-sync-rxdb]], [[sync-spike_spec]]).
- Archived rows reach devices as RxDB deletions (`_deleted: true`), so devices drop them.
- **Archive vs. a later edit from another device:** latest write wins — a later edit brings the note back. The worst case is an archived note reappearing (one tap to fix), never lost writing.

## Inputs and outputs
- **Input:** create, edit, move (between folders), tag, pin/unpin, archive notes; create, rename, move, archive folders; search text and tags.
- **Output:** folder tree, note list per folder (pinned first, then last edited), note editor, search results; data stored on the server, active items cached on each device.

## Acceptance criteria (done when…)
1. Notes can be created, edited, moved, tagged, pinned and archived on PC and Android.
2. Folders can be nested to any depth, renamed, moved and archived.
3. The note list shows each note's title, or its first line when the title is empty — pinned first, then last edited first.
4. Notes can be found by text ("contains") and by tag, offline too.
5. With no connection, notes can still be created and edited; once the connection returns, the changes reach the server and the other device.
6. The same note edited on two devices: the later edit wins, nothing crashes.
7. A new note left empty is never created; clearing an existing note and leaving restores its previous text.
8. Archiving a note or folder removes it from every device's local storage; the row stays in the database with `archived_at` set.
9. Archiving a folder archives everything inside it; restoring it from the Archive page brings all of them back, and only them.
10. Tests for the module's API, sync endpoints, `list_archived()` and `restore()` pass.

## Edge cases and failure modes
- A note moved into a folder that another device archived meanwhile → the folder isn't on the device any more, so the note shows at the **top level**; data unchanged — restoring the folder puts it back.
- A note restored while its folder is still archived → shows at the top level, same rule.
- Moving a folder into its own sub-folder → rejected (would create a loop). Only possible when two devices move folders into each other while offline; the server refuses the second move and that device's folder goes back to the server's position.
- Very long note → no limit planned; note if performance suffers.

## Out of scope
- Links to projects or clients (wait for the project manager module).
- A links/backlinks table and graph view.
- Rendered Markdown preview (can come later; data doesn't change).
- Attachments and images in notes.
- Merging simultaneous edits (CRDTs) — latest write wins.
- Server-side full-text search (Postgres `tsvector`) — device search covers phase 1; RAG later.
- Searching archived notes on the device.
- **Markdown export to the PC (later):** write a `.md` copy of each note to `~/Documents/Spaternum/notes/`, so notes are visible and usable outside the app (Obsidian-style). Requested by Mihail 2026-10-21; not phase 1.

## Client details (block 7)
How the rules above map onto the app's layout ([[client-foundation_spec]]). Added 2026-10-28.

**Screens** (routes, so Android's back gesture walks back through them):
- `/tools/notes?folder=<id>`: a folder, browsed like a file manager (changed 2026-10-28 after Mihail's first look). No `folder` means the top level.
  - The header always says **Notes** (in the editor too), never the folder or note name.
  - **Main area, from the top:**
    - Inside a folder, a **location row**: "‹ <parent name>" ("‹ Notes" for the top level) goes up one level, followed by the current folder's name.
    - The **New note** and **New folder** buttons side by side. New folder opens an inline name box and creates the folder inside the current one.
    - Search.
    - The current folder's **sub-folders**, sorted by name; a tap goes in.
    - Its **notes**: each row is **only the title** (the title, or the first line when it's empty) on one line, cut with "…", with a pin mark if pinned. A tap opens the note (Mihail, 2026-10-28).
  - Going into a folder is a new screen, so Android's back gesture goes back up.
  - **Left side panel / ☰:** only the list of tools.
  - **Tool panel (right):** the **folder tree** for jumping anywhere, then the current folder's details (rename, move, archive). At the top level it shows only the tree.
- `/tools/notes/<id>` — **editor** in the main area: a one-line **Title** box above the plain text box. While the title is empty, the box shows the text's first line in grey as its placeholder, so it looks filled in but follows the text; typing replaces it. The title saves the same way as the text. Tool panel: the folder tree, then the **note's details** — tags, pin, move to a folder, archive.
- **Search** sits above the folder's contents: a text box and the tags in use. While text is typed or a tag is chosen, the list shows matching notes from **all folders** instead of the folder's sub-folders and notes.

**Writing:**
- Every write sets `updated_at` to the device time corrected by the server offset (`serverNow()`), so latest-write-wins works ([[2026-10-20-offline-latest-write-wins]]).
- The editor **saves on its own** a moment after typing stops and when leaving — no Save button, so nothing written is lost.
- **New note:** the editor opens with an id but no row; the row is created at the first save with text. Left empty → nothing is written.
- **Existing note cleared:** an empty text is never saved; on leaving, the note goes back to the text it had when it was opened.
- **Archive** = one local write: `_deleted: true` with a new `updated_at` (otherwise the server keeps its newer row). A folder archive writes only the folder; the server archives what's inside and sends those back as deletions, so they share one `archived_at` and restore together.
- **Contents of a folder archived on this device** are hidden straight away, any depth, until the server's archive of them syncs back (decided 2026-10-28). The device keeps the folder's id and archive time; only items not changed since then are hidden, so a note moved or restored into it later still shows (at the top level, below).
- A note open in the editor follows changes from the other device only while it has no unsaved typing; otherwise the later write wins as usual.

**Folders:**
- A folder or note whose folder isn't on the device shows at the top level — unless that folder was archived on this device (above).
- Move to: every folder except the folder itself and its sub-folders (the loop rule above, checked on the device too). Folder names are trimmed; an empty name is refused.

**Also decided (2026-10-28):**
- Text search ignores upper/lower case. A body of only spaces/new lines counts as empty.
- Several chosen tags = notes with all of them. Tags are trimmed and de-duplicated, kept as typed.
- Folders are sorted by name.
- A new note that was saved while typing and then cleared before leaving is archived (it already has a row, and archiving is the only way to get rid of one).
- Archiving a folder asks for confirmation first, with the number of sub-folders and notes inside.

**Client database:** the RxDB `notes` schema goes to version 1, with a migration that gives every stored note `title: ""`.

**Known limitation (phase 1):** pinning, tagging or moving a note sets `updated_at`, which is also the "last edited" sort key, so the note moves up the list. Fixing it needs a separate edited time (schema change); left for later (decided 2026-10-28).
