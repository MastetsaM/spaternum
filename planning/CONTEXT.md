# CONTEXT — planning

What Spaternum is, why each choice was made, and what's next. Read this folder before writing code.

## What lives here
| Path | Purpose |
|---|---|
| `PRD.md` | What the project is, why, architecture, stack, phases, what's cut — start here |
| `TECH.md` | How it's built: patterns, package versions, dev setup, what not to use |
| `decisions/` | One record per decision: `YYYY-MM-DD-title.md` |
| `risks/risks.md` | Risks with likelihood, impact, mitigation |
| `tasks/tasks.md` | Current phase checklist and pending decisions — check this first in a new session |
| `specs/` | One spec per feature: `feature-name_spec.md` |

## Conventions
- A new decision gets its own record; `PRD.md`/`TECH.md` link to it instead of repeating the reasoning.
- A spec is written and agreed before its feature is built.
- Results of a prototype or test go into its spec's Results section.
- Commands for creating each artifact: see the Planning Artifacts section of the project `CLAUDE.md`.
